Strapi 5 plugin

WhatsApp transport for Strapi.

Magic WhatsApp owns the WhatsApp connection, message delivery, and templates. It starts disconnected and only pairs or sends after an authorized administrator acts.

Features

One Strapi plugin owns WhatsApp transport for the workbench. The connection starts disconnected; booting Strapi does not pair a device or send a message.

Pair only on request

An administrator with connection permission starts pairing. A QR is created only during that action and is returned only through the protected pairing flow.

Manage message templates

Authorized users can list, create, edit, and delete templates stored in the Magic WhatsApp Strapi plugin store.

Send with checks

Sending requires a separate permission. The server validates the international phone number and message length, checks WhatsApp registration, and applies a per-admin rate limit.

Internal Magic Link delivery

The Magic Link plugin can call the registered WhatsApp service to send a bounded-expiry login URL. This is an internal Strapi service contract, not a public endpoint.

Install from GitHub

The package is private on npm. Install it from its GitHub repository instead. npm installs the package dependencies and devDependencies, then runs prepare to build the plugin before installing it.

Install the repository
npm install github:Schero94/strapi-plugin-magic-whatsapp

Enable the plugin in config/plugins.ts or config/plugins.js:

config/plugins.ts
export default () => ({
  'magic-whatsapp': {
    enabled: true,
  },
});

Build the Strapi admin and start the application:

Build and start
npm run build
npm run develop

Strapi 5.57 or a compatible Strapi 5 release and Node.js 22 are required.

Configuration

The plugin has no connection secret or auth-state path option. It accepts an optional socket factory for a host integration or fake transport.

Magic WhatsApp server configuration
OptionDefaultPurpose
socketFactorynullOptional function that creates the WhatsApp socket. Tests can inject a fake socket so they never need a live account.

Unsupported configuration keys are rejected. Do not put credentials or auth-state data in Strapi configuration.

Security and permissions

Every route is an authenticated Strapi admin route with a server-enforced permission. The admin UI checks the same permissions for navigation and controls, but the route policy remains the security boundary.

Pairing and message delivery

  • The service starts in the disconnected state. It does not connect automatically at startup.
  • Pairing starts only after an authorized administrator chooses to connect. The QR is available only to an authenticated administrator with connection permission.
  • Direct and template sends require the send permission. Recipients must use international format, and the server checks that the number is registered before delivery.
  • Messages are limited to 4,096 characters. Sending is rate-limited per admin. Template variables are validated before rendering.
  • Disconnect closes the transport but keeps the saved session. Log out is a separate action that removes the auth-state directory.

Local auth state

Baileys credentials are kept on the Strapi host under ~/.strapi/magic-whatsapp/<app-id>/.whatsapp-auth. The directory is created with owner-only permissions and the plugin rejects a symlinked auth directory. The .whatsapp-auth ignore rule keeps it out of Git. Restrict access to the Strapi process and never copy this directory into source control, logs, issue reports, or shared artifacts.

Pairing and sending affect a real WhatsApp account. Local tests use fake transports and do not pair, request a QR, or deliver messages.

Magic Link service

The Magic Link plugin can resolve the registered magic-whatsapp service and call sendMagicLink({ phoneNumber, loginUrl, expiresInSeconds }). It requires a connected transport, an international phone number, and an HTTPS login URL. HTTP is accepted for localhost only. URLs are limited to 2,048 characters and expiry must be from 1 second to 24 hours. The message includes the login URL and expiry, then uses the same recipient check and send path as other messages. The method returns { success: true } on delivery and throws a sanitized error on failure. This is an internal service call, not an HTTP route.

Fake transport

Unit tests inject socketFactory and use a fake Baileys socket to exercise connection, template, Magic Link, and send behavior. They do not need a WhatsApp account. Keep this pattern for local test and acceptance work.
